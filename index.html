Tu bot de WhatsApp con Inteligencia Artificial, de cero a producción

Tutorial completo basado en la Guía Maestra paso a paso de OpenLivery: conceptos, despliegue, configuración del agente, conexión oficial con Meta Cloud API, pruebas, entrega al cliente y resolución de problemas.

La ilustración resume el recorrido: OpenLivery actúa como puente entre tu agente de IA y Meta.

  • Nivel: principiante a intermedio
  • Duración estimada: 3–5 horas
  • Sin código propio
  • Enfoque: manos a la obra

¿Qué vas a conseguir?

  • Entender qué es un agente conversacional y en qué se diferencia de un chatbot de menús.
  • Saber elegir entre la edición autoalojada (gratuita) y la edición Cloud de OpenLivery.
  • Desplegar la plataforma en un VPS con Docker, o acceder a la versión en la nube.
  • Configurar un agente de IA con identidad, contexto, integraciones y acciones.
  • Cargar una base de conocimiento (PDF y preguntas frecuentes) para que el bot responda con datos reales.
  • Conectar Google Calendar y Google Sheets para agendar y registrar reservas.
  • Vincular el número a la WhatsApp Business Cloud API de Meta con las cuatro credenciales correctas.
  • Probar, publicar y entregar el portal al cliente final.
  • Diagnosticar los fallos más habituales sin depender de nadie.

¿Para quién es este tutorial?

Para personas sin conocimientos técnicos previos que necesitan poner en marcha un bot de atención al cliente para un negocio local, o para agencias que quieren desplegar bots para varios clientes.

Está escrito para que puedas seguirlo aunque nunca hayas usado Docker, Meta for Developers ni una API. Cuando aparece un término técnico, se explica antes de pedirte que lo uses.

CONCEPTOS

Conceptos clave, explicados sin jerga

Antes de tocar un servidor o un portal de Meta, necesitas entender seis ideas. Con ellas, el resto del tutorial se lee casi solo.

1. De los menús rígidos a los agentes que entienden

La automatización de mensajería ha evolucionado desde sistemas rígidos basados en árboles de decisión hacia agentes conversacionales impulsados por Modelos de Lenguaje de Gran Escala (LLM).

Chatbot tradicional

  • Cada opción se programa a mano.
  • Si el usuario escribe algo distinto a lo previsto, se pierde.
  • Mantenerlo exige reescribir flujos constantemente.

Agente conversacional

  • Comprende la intención del usuario.
  • Analiza el contexto del negocio (precios, horarios, políticas).
  • Ejecuta acciones dinámicas: consultar un calendario, registrar una reserva.

Por qué importa: un agente no responde con un menú, responde con información de tu negocio. Eso es exactamente lo que configuraremos en la Fase 4 del procedimiento.

2. Vocabulario esencial

Plataforma de orquestación (middleware)

Sistema central que conecta tres cosas: la API de mensajería (WhatsApp), el proveedor de Inteligencia Artificial (OpenRouter) y las herramientas externas (calendarios, hojas de cálculo, CRM).

En este tutorial ese middleware es OpenLivery. Tú no programas la conexión: la configuras desde un panel.

Tokens: la unidad de cobro de la IA

Los tokens son las unidades básicas de procesamiento de texto en un LLM. Equivalen aproximadamente a una palabra o a un fragmento de palabra.

  • Tokens de entrada (input): instrucciones, contexto del negocio, documentos, historial del chat y mensaje del usuario.
  • Tokens de salida (output): la respuesta que genera la IA.

Entender esto es lo que te permitirá estimar el costo mensual de tu bot (lo verás en la Fase 3 del procedimiento).

API y Webhook: dos direcciones del mismo diálogo

La API permite enviar peticiones a un sistema remoto. El webhook es el mecanismo inverso: recibe notificaciones HTTP en tiempo real cuando ocurre algo, por ejemplo, cuando un usuario envía un mensaje.

Cuando alguien escribe a tu WhatsApp, Meta no «avisa» a tu servidor por arte de magia: hace una petición HTTP a la URL de webhook que tú registraste. Si esa URL falla o no está suscrita al campo correcto, los mensajes simplemente no llegan.

3. ¿Qué es OpenLivery?

OpenLivery es una plataforma de código abierto y marca blanca (white-label) creada por Andrés Sarrazola. Está diseñada para que agencias desplieguen bots de IA para múltiples clientes.

Su arquitectura es multitenant: una instalación aloja varias agencias, y cada agencia aloja varias subcuentas de clientes, con los datos aislados entre sí. Es compatible con WhatsApp, widgets web e integraciones con Instagram DM y Facebook Messenger.

«Marca blanca» significa que tus clientes ven tu marca (tu logo, tus colores, tu dominio), no la de OpenLivery.

5. Los cuatro pilares de un agente

1. Identidad

Nombre del agente, rol, personalidad y tono de comunicación (tú o usted, formal o cercano).

2. Contexto

Información del negocio: servicios, precios, horarios, políticas y las reglas de lo que debe y no debe hacer.

3. Integraciones

Conexiones a sistemas externos: Google Calendar, Google Sheets, CRM u otras herramientas de consulta y registro.

4. Acciones

Lo que el agente puede ejecutar de forma autónoma: agendar, escalar a un humano, cerrar el chat, hacer seguimiento.

6. Glosario completo

Agente conversacional
Programa que mantiene una conversación comprendiendo intención y contexto, y que puede ejecutar acciones.
LLM
Modelo de Lenguaje de Gran Escala. El motor de IA que genera las respuestas.
Prompt de sistema
Instrucciones permanentes que definen el comportamiento del agente. Consume tokens de entrada en cada mensaje.
Token de entrada / salida
Texto que se envía al modelo / texto que el modelo devuelve. Se facturan por separado.
API
Interfaz que permite a un sistema enviar peticiones a otro.
Webhook
URL de tu sistema que recibe notificaciones HTTP en tiempo real desde otro sistema.
URL de Callback
La dirección concreta del webhook que registras en Meta.
Verify Token
Cadena secreta que Meta compara con la tuya para verificar que la URL de callback es tuya.
App Secret
Clave privada de la app de Meta. Se usa para validar la firma HMAC de cada mensaje recibido.
HMAC
Código de autenticación basado en hash. Si la firma no coincide, la petición se rechaza: así se evita que un atacante simule ser Meta.
Phone Number ID
Identificador único del número telefónico en el portal de Meta.
WABA ID
WhatsApp Business Account ID: identificador de la cuenta empresarial de WhatsApp.
Permanent Access Token
Token de larga duración generado desde un Usuario del Sistema. Sustituye al token temporal de 24 horas.
OpenRouter
Servicio que unifica el acceso a modelos de IA de distintos fabricantes con una sola API Key.
Middleware
Capa intermedia que conecta la mensajería, la IA y las herramientas externas.
Multitenant
Arquitectura en la que una instalación sirve a varias organizaciones manteniendo sus datos separados.
White-label
Marca blanca: personalización de la plataforma con la identidad de tu agencia.
VPS
Servidor privado virtual: una máquina Linux alquilada, con IP pública.
Docker / Docker Compose
Sistema de contenedores que empaqueta los servicios de OpenLivery y los arranca juntos con un comando.
SSL / HTTPS
Cifrado del tráfico web. Meta exige HTTPS público para los webhooks.
Embeddings
Representaciones vectoriales del texto que permiten buscar por significado, no solo por palabras exactas.
Búsqueda semántica
Recuperar información comparando significados, no coincidencias literales.
Keyword fallback
Mecanismo de respaldo por palabras clave cuando la búsqueda semántica no devuelve resultados útiles.
MCP (Model Context Protocol)
Protocolo para conectar el agente con herramientas y sistemas externos de forma estandarizada.
SSRF
Ataque que fuerza al servidor a realizar peticiones a destinos internos. OpenLivery protege las herramientas HTTP contra él.
Live Mode (En vivo)
Estado de la app de Meta que la habilita para recibir mensajes reales. En «Desarrollo» los mensajes no fluyen.
Plantilla (template)
Mensaje preaprobado por Meta. Obligatorio fuera de la ventana de 24 horas.
Ventana de 24 horas
Periodo tras un mensaje del usuario en el que el negocio puede responder con texto libre.

PROCEDIMIENTO

Procedimiento completo, fase por fase

Doce fases ordenadas. No saltes ninguna: cada una prepara la siguiente. Si algo falla, cada paso incluye un bloque desplegable con los problemas más probables.

Fase 0 · Requisitos previos

0.1 Infraestructura de servidor

Objetivo: tener una máquina donde alojar OpenLivery (solo si eliges la edición autoalojada).

  1. Contrata un VPS Linux con Ubuntu 22.04 LTS o superior. Motivo: la guía está pensada para esa versión. Resultado esperado: recibes por correo una IP pública y una contraseña o clave SSH.
  2. Instala Docker Engine y Docker Compose en ese servidor. Resultado esperado: los comandos docker y docker compose responden sin error.
  3. Configura un dominio o subdominio con registros DNS apuntando a la IP del VPS. Resultado esperado: el dominio resuelve a tu servidor.
  4. Habilita el certificado SSL para que el panel funcione por HTTPS. Motivo: Meta exige HTTPS público obligatorio para los webhooks. Resultado esperado: el candado de seguridad aparece en el navegador.
Si algo falla
  • Si el dominio no resuelve, espera a la propagación DNS (puede tardar horas) antes de continuar.
  • Sin HTTPS válido no podrás verificar el webhook en Meta: es un bloqueo total, no un aviso.

0.2 Cuenta empresarial de Meta

Objetivo: tener la cuenta que autorizará el envío de mensajes por la vía oficial.

  1. Crea o accede a tu Meta Business Portfolio (antiguo Business Manager). Resultado esperado: ves el panel de tu portafolio empresarial.
  2. Completa la Verificación de Empresa en Ajustes › Información del negocio › Estado de verificación. Motivo: sin verificación no podrás operar la API en producción. Resultado esperado: el estado figura como verificado.
  3. Registra un método de pago válido y asígnalo específicamente a la cuenta de WhatsApp dentro de Meta Business Suite. Resultado esperado: la cuenta de WhatsApp muestra un método de pago activo.
  4. Consigue un número de teléfono exclusivo capaz de recibir SMS o llamadas de verificación, que NO esté registrado actualmente en las aplicaciones móviles de WhatsApp o WhatsApp Business. Motivo: un número en uso no puede registrarse en la Cloud API.

Atención: si el número ya está activo en la app de WhatsApp, deberás eliminarlo de la app antes de registrarlo, o usar el modo Coexistencia (Fase 9).

0.3 Proveedor de Inteligencia Artificial

Objetivo: tener acceso a los modelos de lenguaje que responderán a los clientes.

  1. Crea una cuenta en OpenRouter. Resultado esperado: accedes al panel de OpenRouter.
  2. Genera una API Key. Resultado esperado: obtienes una cadena de texto que deberás guardar en lugar seguro.
  3. Carga saldo. Motivo: sin saldo, el agente no responde aunque todo lo demás esté correcto.

Fase 2 · Configuración de agencia y marca blanca

2.1 Registro del propietario de la agencia

Objetivo: crear la cuenta de propietario y cerrar los registros públicos.

  1. Abre la interfaz web de OpenLivery por primera vez.
  2. Completa el formulario inicial con el nombre de tu agencia, el correo del propietario y una contraseña.

Resultado esperado: accedes al panel de agencia. Al completar este registro, la plataforma cierra automáticamente los registros públicos para proteger el aislamiento multitenant de tu instalación.

Consecuencia práctica: si necesitas crear otra agencia más adelante, tendrás que hacerlo desde dentro, no desde el registro público.

2.2 Personalización de marca blanca

Objetivo: que tus clientes vean tu marca y no la de OpenLivery.

  1. Entra en Ajustes de la Agencia.
  2. Define el nombre de la agencia y un identificador personalizado.
  3. Sube el logotipo y selecciona la paleta de colores corporativa.
  4. Configura un dominio personalizado para el portal de clientes creando un registro DNS tipo CNAME que apunte a tu servidor. OpenLivery gestionará el certificado SSL de forma automática.

Resultado esperado: el portal de clientes se abre bajo tu dominio, con tu logo y tus colores.

Si algo falla
  • Si el dominio personalizado no carga, verifica que el CNAME apunte exactamente al host indicado por la plataforma.
  • El certificado SSL automático puede tardar unos minutos tras crear el registro DNS.

Fase 3 · Integración de OpenRouter y modelos de IA

3.1 Configurar la API Key

Objetivo: dar a OpenLivery acceso a los modelos de lenguaje.

  1. Ve a Configuración › Proveedores de IA.
  2. Pega tu API Key de OpenRouter y guarda los cambios.

Resultado esperado: la clave queda almacenada cifrada en la base de datos y la plataforma puede invocar modelos.

3.2 Selección del modelo de IA

Objetivo: elegir un modelo adecuado para atención al cliente.

OpenLivery permite elegir cualquier modelo disponible en OpenRouter: OpenAI, Anthropic, Google, Meta o DeepSeek, entre otros.

Para bots de atención al cliente, el material recomienda GPT-4o Luna, por su equilibrio entre latencia ultrarrápida, razonamiento preciso y costo reducido.

Verificación pendiente: el nombre y la tarifa de los modelos del catálogo de OpenRouter cambian con frecuencia. Antes de contratar, confirma en el panel de OpenRouter que el modelo existe y a qué precio.

3.3 Entender la estructura de costos de tokens

Objetivo: poder estimar cuánto costará el bot cada mes antes de venderlo.

Cada mensaje que envía el usuario procesa en la IA:

Tokens de Entrada = Prompt de Sistema + Contexto/PDF + Historial de Chat + Mensaje del Usuario

Ejemplo de cálculo mensual: para un negocio con 6.000 mensajes al mes (20 chats al día, 10 respuestas por chat), se procesan aproximadamente 30 millones de tokens de entrada y 1,8 millones de tokens de salida. Con el modelo GPT-4o Luna, el costo total en Inteligencia Artificial es de solo ≈ $3,90 USD al mes.

Este cálculo es el que figura en el material de origen y corresponde únicamente al costo de IA. No incluye el costo de mensajería de Meta ni la infraestructura.

¿Por qué los tokens de entrada cuestan más que los de salida?

Porque en cada interacción se reenvía todo el contexto: el prompt del sistema, la información del PDF y el historial completo de la conversación. Aunque el usuario escriba «Hola», el modelo procesa todo ese bloque como entrada.

Fase 4 · Cliente y configuración del agente

4.1 Crear el cliente (workspace de negocio)

Objetivo: crear la subcuenta aislada del negocio para el que trabajarás.

  1. En el menú principal de la agencia, selecciona Clientes › Nuevo Cliente.
  2. Ingresa el nombre del negocio (por ejemplo, «Barbería Nuclear») y la categoría del sector comercial.
  3. Crea la subcuenta.

Resultado esperado: el cliente aparece en tu listado y puedes entrar en su workspace.

4.2 Configurar los cuatro pilares del agente

Objetivo: definir quién es el agente, qué sabe, con qué se conecta y qué puede hacer.

Entra al cliente creado y selecciona Agentes › Crear Agente.

Pilar 1 · Identidad

  • Nombre del agente: por ejemplo, «Felipe».
  • Rol y personalidad: amable, profesional, ejecutivo.
  • Tono de comunicación: configura el trato explícito (tú o usted) según el mercado.

Pilar 2 · Contexto

  • Descripción del negocio: barbería masculina con servicios de corte y barba.
  • Horarios de atención: lunes a viernes de 8:00 AM a 6:00 PM.
  • Reglas obligatorias:
    • Lo que SIEMPRE debe hacer: dar información de precios, consultar disponibilidad en el calendario y ofrecer agendar la cita.
    • Lo que NUNCA debe hacer: inventar precios, agendar citas en horarios bloqueados o pedir el prefijo de país si no es necesario.

Pilar 3 · Integraciones

Habilita la integración con herramientas externas de consulta y registro (las conectarás en la Fase 6).

Pilar 4 · Acciones operativas

  • Escalamiento a humano: activa la detección automática de frustración o lenguaje ofensivo para pausar la IA.
  • Cierre de conversaciones: activa el cierre automático de chats al cumplir el objetivo de agendamiento.
  • Seguimiento por inactividad: configura mensajes automáticos si el usuario deja de responder.

Resultado esperado: el agente queda creado y asociado al cliente.

Regla de oro del contexto

Todo lo que el agente «no debe hacer» debe estar escrito explícitamente. El modelo no adivina las políticas de tu negocio: si no están en el contexto, no las respetará.

Fase 5 · Base de conocimiento y búsqueda semántica

5.1 Cargar documentación

Objetivo: que el agente responda con los datos reales del negocio.

  1. Ingresa a la pestaña Conocimiento del agente.
  2. Carga un PDF con la lista de precios, el menú o el catálogo.
  3. Añade pares de Preguntas Frecuentes (Q&A) para las consultas más comunes.

Resultado esperado: el agente dispone de información verificable y deja de improvisar respuestas.

5.2 Cómo funciona la búsqueda semántica

Objetivo: entender qué ocurre por dentro para saber qué esperar y qué revisar.

  • OpenLivery genera vectores semánticos almacenados directamente en formato JSON en PostgreSQL.
  • No requiere extensiones complejas como pgvector.
  • El sistema realiza una búsqueda semántica por similitud y cuenta con un mecanismo de respaldo por palabras clave (keyword fallback).
  • Además, admite capacidades multimodales: reconocimiento de imágenes (visión) y transcripción de notas de voz.

Por qué importa: si la búsqueda semántica falla, el respaldo por palabras clave evita que el agente se quede sin información; pero si el PDF no contiene el dato, ningún mecanismo lo inventará correctamente.

Fase 6 · Google Calendar y Google Sheets

6.1 Conectar Google Calendar

Objetivo: que el agente consulte huecos libres e inserte citas.

  1. Ve a Integraciones › Google Calendar.
  2. Autoriza la cuenta de Google del negocio.
  3. Asigna el calendario específico donde el agente consultará la disponibilidad e insertará las citas.

Resultado esperado: la integración figura como conectada y con un calendario asignado.

Si algo falla
  • Autoriza con la cuenta que realmente gestiona la agenda del negocio, no con tu cuenta personal de agencia.
  • Si el agente no ve huecos, revisa que el calendario asignado sea el correcto y no uno vacío.

6.2 Conectar Google Sheets

Objetivo: dejar un registro de cada reserva confirmada.

  1. Ve a Integraciones › Google Sheets.
  2. Crea o vincula una hoja de cálculo con las columnas: Fecha, Hora, Cliente, Teléfono, Servicio y Precio.

Resultado esperado: cada vez que el agente confirme una reserva, escribirá una nueva fila automáticamente.

Copia exactamente los nombres de columna: son los que el agente espera encontrar para escribir los datos en el lugar correcto.

Fase 7 · Aprovisionamiento automático con asistentes de código

7.1 Generar un token de API y automatizar la configuración

Objetivo: omitir la configuración manual en la interfaz usando un asistente de código.

  1. Ve a Configuración › Agentes de IA › Generar Token de API.
  2. Copia el token generado.
  3. Abre tu asistente de código (Codex o Claude Code) y envíale el prompt que aparece a continuación, sustituyendo el marcador del token por el tuyo.
"Con esta información conéctate a OpenLivery [TOKEN_API]. Vas a ver un agente que se llama Felipe. Quiero que te inventes toda la información para una barbería de barrio, conectes mi cuenta de Google Calendar y crees una hoja de cálculo para registrar las reservas. Define los servicios y precios en dólares, establece el tono de comunicación en español y genera un PDF detallado de servicios para subirlo a la base de conocimiento."

Resultado esperado: el asistente ejecuta las llamadas a la API necesarias y configura el agente, las herramientas y la base de conocimiento.

Advertencia de seguridad: el token de API da acceso a tu instalación. No lo pegues en servicios públicos ni lo compartas. Si sospechas que se ha filtrado, genera uno nuevo.

Fase 8 · Conexión oficial a WhatsApp Business Cloud API (Meta)

Regla obligatoria de arquitectura: debes crear una aplicación en Meta por cada cliente individual para evitar conflictos de webhook y descarte de mensajes.

Resumen del proceso de vinculación

  1. Crear la app en Meta (tipo: Otro › Negocio).
  2. Registrar el número y verificarlo mediante SMS o llamada.
  3. Generar el Permanent Access Token desde un Usuario del Sistema administrador.
  4. Extraer Phone Number ID, WABA ID y App Secret.
  5. Guardar las credenciales en OpenLivery y configurar el webhook en Meta.
  6. Cambiar el estado de la app de «Desarrollo» a «En vivo» (Live Mode).

8.1 Crear la app en Meta for Developers

Objetivo: tener la aplicación que representará a este cliente ante Meta.

  1. Ingresa a Meta for Developers (enlace en FUENTES).
  2. Haz clic en Crear App › selecciona el tipo Otro › elige Negocio.
  3. Vincula la app a tu Portafolio Empresarial Verificado.
  4. En el panel de la app, busca el producto WhatsApp y haz clic en Configurar.

Resultado esperado: accedes a la configuración de la API de WhatsApp dentro de tu app.

8.2 Registrar y verificar el número

Objetivo: asociar el número del negocio a la API.

  1. Ve a WhatsApp › Configuración de la API.
  2. Haz clic en Añadir número de teléfono e ingresa el nombre de pantalla (Display Name, por ejemplo «Barbería Nuclear»).
  3. Completa la verificación con el código enviado por SMS o llamada de voz.
  4. Copia y guarda los dos valores que se muestran en pantalla:
    • Phone Number ID
    • WhatsApp Business Account ID (WABA ID)

Resultado esperado: el número figura como registrado y tienes ambos identificadores guardados.

8.3 Generar el token de acceso permanente

Objetivo: obtener un token que no caduque en 24 horas.

No utilices el token temporal de la pantalla de inicio: expira en 24 horas y tu bot dejará de responder sin previo aviso.

  1. Abre Meta Business Suite › Configuración del negocio › Usuarios › Usuarios del sistema.
  2. Selecciona o crea un Usuario del Sistema Administrador.
  3. Haz clic en Asignar activos › Apps, selecciona tu app de WhatsApp y marca Control Total.
  4. Haz clic en Generar nuevo token, selecciona la app y marca obligatoriamente los permisos (scopes):
    • whatsapp_business_messaging
    • whatsapp_business_management
  5. Copia el token generado inmediatamente. Es el Permanent Access Token.

Resultado esperado: tienes un token de larga duración guardado en lugar seguro.

Si algo falla
  • Si no ves la opción de asignar activos, comprueba que el Usuario del Sistema tenga rol de administrador.
  • Si el token no funciona, revisa que ambos scopes estén marcados: sin ellos, Meta rechaza las llamadas.

8.4 Obtener el App Secret

Objetivo: poder validar que los mensajes recibidos provienen realmente de Meta.

  1. En el portal de desarrolladores, ve a Ajustes de la app › Básica.
  2. Haz clic en Mostrar junto a Secreto de la aplicación (App Secret) y cópialo.

Resultado esperado: tienes el App Secret guardado.

Este valor valida la firma digital HMAC de los mensajes recibidos. Si no coincide, las peticiones se rechazan.

8.5 Guardar credenciales y registrar el webhook

Objetivo: unir Meta con OpenLivery para que los mensajes entren y salgan.

  1. En OpenLivery, abre Clientes › [Tu Cliente] › Canales › WhatsApp API.
  2. Ingresa los cuatro valores: Phone Number ID, WABA ID, Permanent Access Token y App Secret.
  3. Copia la URL de Callback y el Verify Token que genera OpenLivery.
  4. Regresa al portal de Meta y ve a WhatsApp › Configuración.
  5. Pega la URL de Callback y el Verify Token. Haz clic en Verificar y guardar.
  6. En la sección Webhooks, haz clic en Administrar y suscríbete obligatoriamente al campo messages.
  7. En la barra superior del portal de Meta, cambia el estado de la app de Desarrollo a En Vivo (Live Mode).

Resultado esperado: el canal figura como conectado y la app está en modo En vivo.

Si algo falla
  • La verificación del webhook falla: casi siempre es el certificado SSL o un Verify Token que no coincide exactamente.
  • Los mensajes no llegan: revisa que estés suscrito al campo messages y que la app esté En vivo.
  • Llegan al cliente equivocado: probablemente compartiste una misma app de Meta entre dos clientes.

Ejercicio 1 · Distinguir las dos ediciones

Enunciado: una agencia quiere gestionar 30 clientes con presupuesto de licencia cero y tiene un administrador de sistemas propio. ¿Qué edición le conviene y qué obligaciones asume?

Ver solución

Edición autoalojada. Es gratuita bajo licencia MIT y permite subcuentas e instancias ilimitadas. A cambio, la agencia asume: administrar el VPS, actualizar los contenedores, hacer copias de seguridad de PostgreSQL y configurar manualmente los certificados SSL y las credenciales de Meta.

Por qué no la Cloud: el plan Unlimited, con clientes ilimitados, cuesta $349 USD al mes; con 30 clientes y capacidad técnica interna, la autoalojada elimina ese costo recurrente.

≈ $3,90 USD al mes, según el ejemplo recogido en la guía. Recuerda que este importe cubre solo la IA: hay que sumar el costo de mensajería de Meta y, si aplica, la infraestructura.

Autoevaluación: 21 preguntas

Intenta responder antes de desplegar cada respuesta. Están organizadas por nivel.

Nivel básico

1. ¿Qué es OpenLivery y cuál es su función principal dentro del ecosistema de automatización con IA?

OpenLivery es una plataforma de código abierto y marca blanca (white-label) diseñada para que agencias y empresas puedan construir, desplegar y administrar agentes de Inteligencia Artificial para clientes finales en canales de mensajería como WhatsApp y widgets web. Su función principal es actuar como orquestador (middleware) que conecta el número de WhatsApp con los modelos de lenguaje de IA (a través de OpenRouter) y herramientas externas (como calendarios o bases de datos), ofreciendo además una bandeja de entrada unificada para intervención humana.

2. ¿Cuáles son las diferencias principales entre la versión Self-Hosted (autoalojada) y la versión Cloud de OpenLivery?

La versión Self-Hosted es 100% gratuita bajo licencia MIT, se instala en un servidor propio mediante Docker y permite crear cuentas de clientes ilimitadas, pero requiere que el usuario gestione la infraestructura, las actualizaciones y configure las credenciales de WhatsApp manualmente. Por su parte, la versión Cloud es una suscripción gestionada ($49 a $349 USD/mes) que incluye el alojamiento, actualizaciones automáticas, conexión de WhatsApp en un clic y herramientas integradas como Google Calendar.

3. ¿Cuáles son los cuatro componentes o pilares fundamentales que definen a un agente en OpenLivery?
  1. Identidad: nombre, rol, comportamiento y tono de comunicación del bot.
  2. Contexto: información del negocio (servicios, precios, horarios, políticas) y reglas de lo que debe y no debe hacer.
  3. Integraciones: conexiones a sistemas externos como Google Calendar, Google Sheets o CRM.
  4. Acciones: funciones autónomas como agendar citas, escalar a un humano, dar seguimiento o cerrar chats resueltos.
4. ¿Qué es OpenRouter y por qué se utiliza como proveedor de IA en OpenLivery?

OpenRouter es un servicio unificado de API que da acceso a una amplia variedad de modelos de Inteligencia Artificial de diferentes empresas (OpenAI, Anthropic, Google, Meta, DeepSeek, entre otras) mediante una sola clave de API. Se utiliza en OpenLivery porque permite elegir el modelo más conveniente para cada agente y registra de forma transparente el costo exacto por cada respuesta generada.

5. ¿Qué diferencia existe entre conectar WhatsApp mediante código QR y mediante la API Oficial de Meta Cloud?

La conexión por código QR vincula la sesión de un WhatsApp Web mediante librerías como whatsmeow: es útil para pruebas rápidas, pero acarrea un alto riesgo de que Meta bloquee o banee el número por uso no autorizado en producción. La API Oficial de Meta Cloud conecta el número directamente a la infraestructura oficial de Meta, garantizando estabilidad jurídica, soporte para producción, acceso a plantillas y cero riesgo de baneo por el canal, a cambio de pagar las tarifas oficiales por conversación impuestas por Meta.

6. ¿Cuántos mensajes o conversaciones gratuitas otorga Meta al mes para un número conectado a la API Cloud?

Meta otorga a cada cuenta de WhatsApp Business un volumen de 1.000 mensajes/conversaciones gratuitas al mes. Todos los mensajes entrantes creados por los usuarios hacia el negocio son gratuitos, y los cobros de Meta solo se aplican a las conversaciones enviadas una vez consumido ese cupo de 1.000 mensajes.

7. ¿Qué tipo de información se puede cargar en la base de conocimiento de un agente?

Se pueden cargar textos manuales con descripciones del negocio, archivos en formato PDF (listas de precios, catálogos, menús) y pares estructurados de preguntas y respuestas frecuentes (Q&A). Toda esa información se procesa semánticamente para que el agente consulte los datos exactos al responder.

Nivel avanzado

8. ¿Cuáles son las cuatro credenciales obligatorias que deben obtenerse en Meta para conectar la WhatsApp Business Cloud API?
  1. Phone Number ID: identificador único del número telefónico asignado en el portal de desarrolladores de Meta.
  2. WhatsApp Business Account ID (WABA ID): identificador de la cuenta empresarial de WhatsApp.
  3. Permanent Access Token: token de larga duración generado desde un Usuario del Sistema en Meta Business Suite.
  4. App Secret: clave secreta de la aplicación de Meta, utilizada para validar la autenticidad de los webhooks mediante HMAC.
9. ¿Cómo se genera el token de acceso permanente para evitar que la conexión venza en 24 horas?

Se ingresa a Meta Business Suite › Configuración › Usuarios › Usuarios del sistema. Se selecciona o crea un Usuario del Sistema de tipo Administrador, se le asigna el activo de la aplicación de WhatsApp con permiso de Control Total y se hace clic en Generar nuevo token, seleccionando la app y marcando obligatoriamente los permisos whatsapp_business_messaging y whatsapp_business_management.

10. ¿Cómo funciona la regla de la «Ventana de Servicio de 24 horas» de Meta y qué ocurre cuando expira?

Cuando un cliente envía un mensaje al bot, se abre una ventana de servicio de 24 horas en la que el negocio (o el bot de IA) puede responder de forma libre mediante texto sin restricciones de formato. Cada vez que el cliente responde, la ventana se reinicia. Si pasan 24 horas sin que el usuario escriba, la ventana se cierra y el bot ya no puede enviar texto libre: para volver a contactar al cliente debe enviarse obligatoriamente una plantilla de mensaje aprobada previamente por Meta.

11. ¿En qué consiste la función de «Escalamiento a Humano» y cómo se activa en OpenLivery?

Es la capacidad del sistema de pausar la respuesta automática del agente para permitir que un operador tome el control manual de la conversación. Se activa de forma automática cuando el sistema detecta frustración, lenguaje ofensivo o una mala experiencia, o de forma manual cuando un agente humano presiona el botón «Tomar control» desde la bandeja de entrada centralizada.

12. ¿Por qué los tokens de entrada consumen la mayor parte del costo en los modelos conversacionales?

Aunque el mensaje del usuario sea corto (por ejemplo, «Hola»), cada petición al modelo incluye el mensaje más todo el contexto del agente: el prompt del sistema, la información extraída de los PDF y el historial previo de la conversación. Como todo ese bloque debe procesarse en cada interacción como token de entrada, el volumen de entrada es significativamente mayor que el de salida.

13. ¿En qué consiste el modo de conexión «Coexistencia» y cuál es su utilidad práctica?

Permite vincular la API Oficial de WhatsApp Cloud a un número que ya tiene activa la aplicación móvil WhatsApp Business. Los mensajes entrantes se reciben y se responden tanto en el teléfono del dueño del negocio como en la plataforma de OpenLivery, lo que resulta ideal para negocios que no desean perder la aplicación móvil ni cambiar de número telefónico.

14. ¿Cómo valida OpenLivery que los mensajes recibidos provienen realmente de Meta y no de un atacante?

Utiliza la credencial App Secret guardada en la configuración del canal para calcular el código de autenticación de mensajes basado en hash (HMAC) de cada solicitud entrante. Si la firma digital enviada por Meta en el encabezado de la petición no coincide con la firma calculada con el App Secret en el servidor de OpenLivery, la solicitud se rechaza de inmediato.

Nivel pro

15. ¿Cuál es la arquitectura de microservicios de OpenLivery y qué tecnologías utiliza en su stack autoalojado?
  1. apps/api: backend REST en FastAPI (Python) con SQLAlchemy y Alembic para la lógica de negocio, el modelo de datos y la orquestación de IA.
  2. apps/web: frontend en Next.js (React / TypeScript / Tailwind CSS) que sirve el dashboard de agencia, el portal de clientes, el playground y el widget web.
  3. apps/whatsapp: puente de mensajería en Go con la librería whatsmeow para conexiones por QR.

La persistencia reside en PostgreSQL y la entrada de tráfico la gestiona el proxy inverso Caddy.

16. ¿Cómo se puede automatizar el aprovisionamiento completo de un agente sin usar la interfaz gráfica?

Se genera un token de API de agente desde la configuración de OpenLivery y se le proporciona a un asistente de código (Codex o Claude Code) junto con un prompt estructurado en lenguaje natural. El asistente se conecta a la API de OpenLivery con ese token y ejecuta automáticamente las peticiones necesarias para definir nombre, tono y contexto del negocio, crear y vincular calendarios de Google Calendar y hojas de Google Sheets, y generar e insertar el PDF con precios y servicios en la base de conocimiento.

17. ¿Cómo se garantiza el aislamiento multitenant y la marca blanca en los portales de clientes?

A nivel de base de datos, cada consulta e inserción está estrictamente delimitada por los identificadores agency_id y client_id. Para la marca blanca, la agencia configura su logotipo, colores e identificador, y los clientes acceden a su propio portal publicado en un dominio o subdominio personalizado mediante un registro DNS CNAME que apunta al servidor de OpenLivery, con certificado SSL generado automáticamente y sin mostrar ninguna mención a la marca OpenLivery.

18. ¿Por qué es obligatorio usar una aplicación de Meta independiente por cada cliente?

Porque cada aplicación creada en Meta Developers tiene una única URL de Callback configurada. Como OpenLivery asigna una URL de callback específica para cada canal de cliente, si se usa la misma app para dos clientes todo el tráfico se dirigirá a la única URL registrada: los mensajes destinados al segundo cliente llegarían a la URL del primero y serían descartados por discordancia de número, de modo que nunca serían respondidos.

19. ¿Cómo funciona el almacenamiento y la búsqueda de la base de conocimiento sin extensiones vectoriales?

OpenLivery utiliza un enfoque de embeddings portátiles almacenados en formato JSON directamente en la base de datos. Al realizar una consulta, el sistema evalúa los vectores JSON para la recuperación semántica y, en caso de fallo o inconsistencia, ejecuta un mecanismo de respaldo automático basado en búsqueda por palabras clave (keyword fallback), lo que simplifica el despliegue sin depender de extensiones como pgvector.

20. ¿Cómo influye la ubicación geográfica del destinatario en la estructura de costos de WhatsApp Cloud API?

Meta establece tarifas por conversación muy desiguales según el país del número receptor. Para 5.000 mensajes de servicio, el costo en Colombia es de aproximadamente $4 USD, en México $42 USD, en España y Chile $100 USD, en Argentina $130 USD, y Alemania tiene la tarifa más alta del mercado. Para una agencia, esto implica que en países con tarifas bajas el costo de mensajería puede absorberse en el paquete comercial, mientras que en países con tarifas altas debe trasladarse e informarse con transparencia al cliente final.

21. ¿Cómo se extienden las capacidades de un agente con el protocolo MCP y herramientas HTTP?

OpenLivery permite registrar herramientas personalizadas mediante herramientas HTTP (que ejecutan peticiones a endpoints REST externos con parámetros en URL o cuerpo, y cabeceras encriptadas protegidas contra ataques SSRF) y mediante servidores MCP (a través de HTTP o Server-Sent Events). Al vincular un servidor MCP, OpenLivery descubre dinámicamente las herramientas expuestas, lo que permite al agente consultar sistemas complejos, validar conexiones antes de guardar y registrar el uso de cada herramienta en cada respuesta del usuario.

La mayoría de los fallos de un bot de WhatsApp se concentran en cinco puntos: el token, el webhook, la suscripción al campo messages, el estado de la app y el saldo de la IA. Empieza siempre por ahí.

Los seis errores que más tiempo hacen perder

1. Usar el token temporal de 24 horas

Qué pasa: todo funciona el primer día y al siguiente el bot deja de responder sin haber cambiado nada.

Por qué ocurre: se copió el token de la pantalla de inicio de Meta, que caduca en 24 horas.

Cómo se corrige: genera un Permanent Access Token desde Usuarios del Sistema, con Control Total sobre la app y los dos permisos marcados.

2. Compartir una misma app de Meta entre dos clientes

Qué pasa: el segundo cliente nunca recibe respuestas.

Por qué ocurre: cada app de Meta tiene una única URL de callback. Si dos clientes comparten app, todo el tráfico va a la URL del primero y los mensajes del segundo se descartan por discordancia de número.

Cómo se corrige: crea siempre una app de Meta por cliente.

3. Olvidar la suscripción al campo «messages»

Qué pasa: el webhook se verifica correctamente, pero no entra ningún mensaje.

Por qué ocurre: la verificación solo comprueba la URL; la entrega real exige suscribirse a los campos concretos que quieres recibir.

Cómo se corrige: en la sección Webhooks de Meta, pulsa «Administrar» y suscribe el campo messages.

4. Dejar la app en modo Desarrollo

Qué pasa: las pruebas internas funcionan, pero los clientes reales no obtienen respuesta.

Cómo se corrige: cambia el estado de la app a «En vivo» (Live Mode) en la barra superior del portal de Meta. Es el último paso del proceso de vinculación y el más fácil de olvidar.

5. Registrar un número que ya está en la app de WhatsApp

Qué pasa: Meta no permite completar el registro.

Cómo se corrige: usa un número exclusivo que no esté registrado en las apps de WhatsApp o WhatsApp Business, o utiliza el modo Coexistencia si necesitas mantener la app móvil activa.

6. Confiar en el código QR para producción

Qué pasa: la cuenta puede ser bloqueada por Meta en cualquier momento.

Cómo se corrige: usa el código QR solo para pruebas locales y migra a la API oficial antes de entregar el bot a un cliente real.

Errores de proceso (no técnicos)

  • Configurar el agente antes de tener la plataforma estable. Si el despliegue falla después, pierdes el trabajo de configuración.
  • Conectar Meta el primer día. Es el paso más frágil: déjalo para el final, cuando todo lo demás ya funcione.
  • No probar el bloqueo de calendario. Un bot que agenda sobre horarios ocupados genera un problema real con el cliente final.
  • Entregar el portal sin credenciales al dueño del negocio. El objetivo del proyecto incluye la entrega, no solo la puesta en marcha.
  • No programar copias de seguridad. Sin un volcado periódico de PostgreSQL, un fallo del servidor borra todo el trabajo de configuración.

Método de diagnóstico recomendado: ante cualquier fallo, comprueba en este orden — (1) ¿la app está En vivo?, (2) ¿está suscrita a messages?, (3) ¿el token es permanente y tiene ambos permisos?, (4) ¿el webhook está verificado con SSL válido?, (5) ¿hay saldo en OpenRouter? En el 90% de los casos el problema está en los tres primeros puntos.

Los cinco puntos críticos del proyecto

  1. HTTPS público válido. Sin él, el webhook no se verifica.
  2. Token permanente con los dos permisos. Sin él, todo funciona un día y luego no.
  3. Una app de Meta por cliente. Sin esto, los mensajes se cruzan o se descartan.
  4. Base de conocimiento cargada. Sin ella, el agente inventa.
  5. Modo En vivo. Sin él, los clientes reales no obtienen respuesta.

Qué hacer después de entregar

  • Supervisar la bandeja unificada durante la primera semana.
  • Usar «Tomar control» cuando detectes conversaciones que la IA no resuelve, y «Devolver a la IA» al terminar.
  • Revisar el consumo de tokens para ajustar el modelo si el costo crece.
  • Mantener el volcado de PostgreSQL al día y guardarlo fuera del servidor.
  • Renovar o revisar los tokens y las credenciales de Meta de forma periódica.
